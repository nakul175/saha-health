# Protected field timing continuation — software boundary

This batch supplies an encrypted field capture wrapper and an audited own-session continuation interface. The field notebook lifecycle hooks are a separate integration batch; this commit does not claim those UI hooks are wired or physically tested.

The wrapper accepts the existing notebook writer, current book and prepared-draft identity. Optional policies, counters, sessions and stable pending metadata UUIDs live only inside that encrypted book. Positive workspace actor/care-role checks establish an opt-in collection preference; restoring it while offline does not establish current server authority. Every upload obtains a fresh actor-bound policy and the server compares the original expected actor before writing. A stable disabled policy creates no measurement write. Genuine transport failure retains metadata; positive authority refusal returns denial for the caller to lock without writing.

An actual prepare receipt creates a zero-time capture origin. Explicit successful device saves can seal active foreground intervals, with a 30-second idle cutoff. Only the selected editable prepared draft accrues time. An actual durable sync marker permits a segment against its original sync receipt, with unchanged clinical key/body hash. Replayed metadata acknowledgement drains the same encrypted UUID. No field sync or offline save completes a visit: missing or unflushed intervals remain unknown.

GET attribution with the strict visitId query returns at most 32 open encrypted-field sessions for the current actor only, including for an organisation owner. Current care role, enabled config, normal patient scope and editable visit are checked before the read; a durable fixed-detail read audit precedes a fresh config/membership/patient/visit recheck. Another actor's sessions are never returned. Audit failure refuses disclosure. The online hook reloads own field sessions when the selected draft/version changes; a real online confirmation closes its primary session and genuinely recovered companions. Companion completions add zero seconds, so already recorded field intervals are not repeated.

Migration 0026 changes the receipt/stage/phase uniqueness to include session identity. This permits one actual confirmation receipt to close multiple real origins while retaining unique sample IDs and a partial index restricting each prepare receipt to one stage origin. It rebuilds the exact table inside the migration transaction, copies every column unchanged, retains checks/FK and restores indexes. Existing 0021 is unchanged; db/schema and data-exit migration metadata agree with 0026. Existing audit history is untouched.

Validation: 10 field wrapper contracts, 8 populated SQLite migration contracts, and 15 actual local Worker/D 1 route/receipt/report checks passed. The D 1 witness populates the old 0021 shape, proves a deliberately failing late batch restores its exact schema/rows, applies 0026 without changing any old sample or audit-chain bytes, then closes app+field origins under one confirm receipt with 15 online seconds plus 20 previously recorded field seconds. The report covers one visit at 35 seconds; stable-key retries add no sample, other-actor completion is refused, and closed sessions are unavailable. Faulted read audit and post-audit membership withdrawal refuse the continuation response.

Time is client reported, not externally observed. Completed-visit pilot comparability, demonstrated savings, physical phones and external ticket-system linkage remain acceptance work. Existing internal support/intervention ledgers are not external helpdesk evidence. Pending field UI integration, memory-only online queue loss and absent legacy origin receipts remain explicitly unknown coverage.
