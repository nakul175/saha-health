# Encrypted field capture lifecycle

The field notebook and app offline screen now call the optional encrypted capture wrapper after their existing scope/privacy gates. Registration and durable offline-open logic remain intact: presentation CAS factories clone the latest book, the metadata-only writer reserves the same chain, clones the latest book, and checks original owner/key/epoch before encryption and immediately before CAS, and denial locks the notebook without a later measurement write.

A positively authorized care workspace updates its actor-bound collection preference. Preparing a visit uses an explicit original command UUID without changing its clinical body; after durable grant/presentation storage the wrapper seals a zero-time capture origin. Input/change events inside the current prepared editor start the foreground timer. Explicit successful device save and fresh sync preflight seal accumulated active seconds, with a 30-second idle cutoff. Default-disabled capture produces no timing session, policy preference, measurement queue or measurement POST.

Clinical sync retains its original pending key/body and accepted sync reference. Only a genuinely observed transport or 5 xx uncertainty can queue the fixed client-sync-unknown counter. After clinical acceptance and its local durable synced marker, the wrapper queues the receipt-linked segment. Measurement transport cannot repeat the clinical command or convert a clinical refusal into acceptance. Metadata lost acknowledgements retain the encrypted UUID; subsequent positive workspace load can retry that metadata and drain a recorded or replayed acknowledgement. Actor comparison happens on the trusted server before writing.

The app can retrieve only its own saved field sessions through the audited current-scope continuation route. A real online confirmation completes its existing app origin and genuine field companion; the companion adds zero seconds because the field segment already contains its reported time. No offline save or sync completes clinical work. Original body hashes, registration wire proofs, privacy tombstones and offline-open queues are preserved through notebook clones.

Both service workers include only the two new fixed public JavaScript assets and retain their same-origin, redirect and MIME guards. They cache no API response, patient content or authenticated HTML. Existing minimal-DOM suites use the actual capture factory with their timer isolated; no clinical assertions were relaxed.
