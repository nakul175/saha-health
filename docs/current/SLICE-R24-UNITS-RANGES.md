# Development slice r24 — further units and age/sex/pregnancy-specific value ranges

3 October 2026 (IST). Builds on slice 2i (units and reasoned overrides, `saha-value-ranges-0.1.0`) and slice 2c/2e (per-measurement source, author and verification). Synthetic data only; formal acceptance unchanged. BR-DATA-05 stays partial: approved clinical ranges and their governance remain outstanding.

## What changed

- **Further units, converted on the server with the entered value kept.** Blood pressure is now accepted in kilopascals (kPa, 1 kPa = 7.50062 mmHg, one decimal) in addition to mmHg, and gestational age in weeks + days (`20+3` = 20 weeks 3 days, converted to decimal weeks to two decimals) in addition to weeks, through the existing optional `entered` object in the facts. The `entered` object is now keyed by all six value fields (weight, temperature and cough duration keep their slice 2i units `lb`, `degF` and `wk`). The contract is unchanged from slice 2i: the unit is always stated by the person entering the value, nothing guesses it, the converted base value is stored in the usual field and the entered value and unit are kept beside it. A base-unit value that disagrees with the conversion is refused; an unknown or unsupported unit and a malformed weeks+days entry are refused. `convertEntered` and `normaliseUnits` in `lib/saha/fact-provenance.ts` now handle the new fields, and `checkFacts` converts them before the range check.
- **Age-, sex- and pregnancy-specific placeholder ranges.** A new versioned configuration, `saha-value-ranges-0.2.0` (`POPULATION_RANGES` in `lib/saha/fact-provenance.ts`), keyed by an optional age/sex/pregnancy context (`RangeContext`), mirrors the slice 2i style and carries the same label "engineering placeholder — not clinically approved": no clinical authority is claimed and no one has approved the numbers. Two illustrative groups are defined — children under 18 (lower systolic/diastolic and weight ranges) and pregnancy (wider systolic/diastolic and weight ranges) — each overriding only the fields it names; every other field keeps the slice 2i range. `valueTier`, `rangeProblem` and `rangeSelection` take the optional context and fall back to `saha-value-ranges-0.1.0` exactly when no context is supplied or no group matches, so the default behaviour is unchanged.
- **`checkFacts` honours the context.** `checkFacts(input, now, context?)` accepts an optional `RangeContext`; without it the slice 2i ranges apply. A value inside the default range but outside a population-specific range is treated as unusual and needs a reason, exactly as before. `rangeContextFor(person)` is a pure helper that infers the context (pregnancy from a Maternal care programme or an active maternal enrolment).
- **Overrides keep the entered kPa value.** The slice 2i override recording (`recordOverrides` in `lib/saha/fact-verification.ts`) now reads `facts.entered[field]` for every value field, so an unusual blood pressure entered in kPa records its entered value and unit in the override, alongside the stored mmHg value, exactly as lb/°F/wk already do.

## Evidence

- 24 contract checks (`tests/value-ranges-context-contract.mjs`): kPa and weeks+days conversion with the entered value kept; the schema accepting kPa and weeks+days and refusing an unknown unit; a base value that disagrees with the kPa conversion refused; a malformed weeks+days entry refused; entered text and tidying; the population ranges configuration (version, label, two groups); context-aware `valueTier` (paediatric and pregnancy tiers, and the default when no match); `rangeSelection` returning the paediatric override with slice 2i fallbacks and the default version for a non-matching context; `rangeProblem` accepting 150 mmHg by default and refusing it under a pregnancy context; `rangeContextFor`; and `checkFacts` honouring a pregnancy context.
- `tsc --noEmit` reports no errors in the changed files (`fact-provenance.ts`, `core.ts`, `fact-verification.ts`, `types.ts`); the repository has unrelated pre-existing errors in other modules and in other agents' in-progress work.

## Limits

- The ranges (both `saha-value-ranges-0.1.0` and `saha-value-ranges-0.2.0`) are engineering placeholders. They are not clinically approved; the paediatric and pregnancy groups are illustrative numbers, and no clinical authority is claimed. Approved clinical ranges and their governance remain outstanding for BR-DATA-05.
- The population-specific ranges are available through `checkFacts`'s optional context and `rangeContextFor`, but the server's existing save path still calls `checkFacts` without a context, so the default slice 2i ranges continue to apply on the live save path until a follow-up wires the person's context through. This preserves the default behaviour exactly (a deliberate choice per the isolation rules).
- The React visit screen and field notebook still offer only the slice 2i units (lb, °F, wk); the server accepts kPa and weeks+days, but the UI pickers are not yet extended. The field notebook keeps its own copy of the ranges and units; a contract check compares `VALUE_RANGES` and `ALT_UNITS` (unchanged by this slice) with the notebook mirror.
- Only blood pressure (kPa) and gestational age (weeks + days) are added; other units (for example height, months) and range checks for programme answers remain outstanding (the latter is part of R24's full scope but is not built in this slice).
- Overrides, FHIR notes and the unusual-value flow keep the stored base value (mmHg/weeks); the entered unit is note text only, as in slice 2i.
