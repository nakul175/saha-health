# Contact import and retained batch reversal

5 October 2026. B08 / BR-DATA-11 bounded contacts clause, built on canonical1d388bd2. Existing enrolment, identifier and historical-visit import machinery remains. Programme answers, attachments, structured notes, cross-source conflict queues and wider batch reversals remain separate unfinished work. Formal acceptance and issuer/clinical approval are unchanged.

The existing record-import route now previews CSV contacts for existing records by Saha record ID or exact recorded identifier. Supported columns are person, method, destination, ownership, language, timezone, from, to, private_contact, reference and source_system. The existing synthetic contact contract is preserved: destinations are empty or TEST- identifiers; real phone numbers are refused. Header/UTF-8/100-row bounds remain. Contacts cannot overwrite existing preferences, and duplicate rows, bad hours/timezones/source references, merged or out-of-scope records and retained-history capacity are rejected. Unknown and outside-scope people receive neutral reasons; rejection exports contain row numbers/reasons, not contact values.

A dry run returns current accepted record IDs/versions, counts, raw-file SHA-256 and the plan hash, without contact destinations or source references. Apply recomputes the exact classified file and current supervised normal care/purpose scope. Imported contact permission is always false. It creates neither messages nor consent grants; a current care worker must separately record any contact permission through the existing consent-aware command. Applied contacts retain per-person source-system/file/row/batch/plan/importer/time lineage and an original preference snapshot; patient versions, per-person revisions, counted chained batch audit and body-bound receipt persist atomically. Confirmed visits remain byte-equivalent.

The matching phone/browser panel supports preview/apply and reviewed reversal of the just-applied batch or a saved batch ID after reload. The completion panel exposes the full copyable batch ID; phone recovery reads that ordinary UI value before reload. Reversal requires access to every batch record, exact unchanged imported preferences and a fresh version-bound reversal plan. Edited contacts or contacts with permission cannot be overwritten. An accepted reversal clears only the current unchanged preferences and appends withdrawal evidence on each retained source entry; it does not delete the source snapshot, confirmed records, revisions or original receipt. Original and reversal receipt replays repeat current all-person/purpose authority and create no duplicate mutation. Batch retention remains bounded at100 source entries per person; full history refuses rather than discarding prior evidence.
