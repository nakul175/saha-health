# Clinical dispatch checks across the authority audit

5 October 2026. Follow-up to SERVICE-DISPATCH-REVIEW.md. The historical `open-domain-findings.json` is retained unchanged: it records the original maintenance/consent race allowing one clinical POST.

`serviceDispatch` now accepts an explicit send, lookup or probe intent and a caller-owned authorization callback. A fresh membership read binds current patient/programme/facility scope. Clinical sends/probes recheck maintenance, the initiating membership version/role, normal patient scope and the applicable purpose grant. The domain callback runs before service authority audit and again on the fresh checkpoint after that audit. Without a service binding, domain checks still run on the fresh execution-boundary read; no additional service audit is invented.

All existing dispatch callers declare intent. EHR repeats actual `ehrAccess`, `publishAuthority`, operation and `sendBlock` checks, plus prepared person/consent versions, running checkpoint/hash and write window. MIS repeats `deliveryCurrent`, operation, sign-off/dispute checks and operation ID. Agent execution repeats `current` and source minimisation; evaluation repeats its authorization/provider/manifest checks and running case. Independent community and image providers repeat their actual access/current validators and running input hash. Aggregate sends repeat reporting scope, destination, minimisation, approval, prepared source record versions and operation ID without recording the same release twice. Mock destination enrolment repeats active episode, person version, destination and approval/checkpoint checks. The legacy command adapter records its external-request audit before the final service/domain checkpoint, eliminating an additional awaited audit after the gate. Owner image-connection probes now gate immediately before transport, after reading the bounded synthetic fixture body.

Receipt lookups are explicit. They require current identity/scope/service/destination/checkpoint authority but do not acquire a new clinical-send permission and do not post a clinical body. EHR and MIS uncertainty can be reconciled during maintenance and after clinical consent/purpose withdrawal. Existing independent-provider outer lookup policy is unchanged. A refused lookup remains unresolved; no resend is authorized.

Validation: 100 dispatch gate checks; 33 actual EHR execution checks, including 20 mutations at both audit boundaries with zero clinical POSTs; 16 MIS execution checks, including five during-audit mutations with zero payload requests. The EHR/MIS receipt tests each resolve an uncertain write during maintenance after consent and purpose withdrawal using identifier/key-only lookup. Existing eight independent frontline handler checks (109), mock enrolment checks (45), aggregate delivery (12), aggregate checkpoint population (4) and agent provider contract (25) pass. Tests use real domain validators with injected transport/CAS persistence; frontline uses actual SQLite-backed handlers. TypeScript and the final application build pass, with the existing client chunk-size warning. No hosted/provider/clinical acceptance is claimed.

A broader actual local HTTP/D1 regression on this isolated base (150dd3fd) stopped in `data-exit-smoke.mjs:36` while parsing an undefined verifier subprocess output after a 200 data-exit response. `data-exit-smoke` launches `node` by name; this shell has no `node` in PATH, although the top-level suite used the bundled absolute executable. This is recorded as a test environment failure, not an export policy finding. The lead will rerun with bundled Node in PATH; no full HTTP pass is claimed. Dedicated passing evidence is under `tests/evidence/service-dispatch-review/domain-*`; the original findings remain separate.
