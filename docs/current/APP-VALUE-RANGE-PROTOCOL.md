# Captured value range publication — A04

This batch connects the existing illustrative population ranges to the authenticated browser app, shared encrypted field notebook, server save, assistant application, historical visit import, registration sync and independent confirmation paths. It does not introduce thresholds or clinical approval. The 0.1.0 default and 0.2.0 child/pregnancy numbers are the existing engineering examples. Sex is retained in the context binding; no new sex-specific thresholds are invented.

Owners stage one of the two compiled policies with a monotonically increasing publication version and reason. A different active clinician reviews the exact stored manifest hash. An owner can publish only that reviewed hash while the reviewer still holds the same membership authority. Population examples can be activated only in synthetic or training environments. The exact manifest, pending clinical-approval label, review and append-only publication/supersession history are retained. Limits refuse new entries rather than trim evidence. `/api/value-range-protocols` allows owner/clinician reads only; commands use the existing authenticated command receipts, replay authorization, audit chain and optimistic organisation persistence. No new migration, provider, credential or message delivery exists.

Organisation & team → Value range publications exposes staging, exact manifest/history review, publication and retirement in the browser and `/app` phone frame. The capture form and notebook show the pinned policy version and applied intervals. Unusual-value review shows the original unit, canonical quantity, source author, exact intervals and captured range version separately from measured/reported source and imported lineage.

New visits pin the selected manifest hash, publication and compiled versions, context/group and exact intervals. Historical visits without a capture retain the original default behavior. Existing drafts, signed packets, confirmed records and imports are not reinterpreted when an owner publishes or retires a policy. Correction drafts copy the original capture. Signed field grants contain an optional capture snapshot; old schema-1 packets remain readable. Server sync validates the server visit's capture, never an offline client's suggested thresholds.

Changing age, sex or pregnancy/programme context blocks save, assistant application, unusual-value confirmation and visit confirmation until explicit draft review. The refresh command requires current patient/visit versions and a reason, preserves prior captures and override/confirmation history, and clears current reasons for a fresh review. Each binding gets a new identity even if the patient later returns to an earlier context: an old clinician confirmation cannot authorize the new binding. Confirmed records show changed current context as an informational difference and retain their original evidence.

Imports pin the policy and current patient context at import, not a claim about historic pregnancy. Dry-run hashes include the selected capture; applying a stale plan re-plans against current context/policy. Imported observations remain confirmed IMPORTED history with no implied clinical sign-off. Values beyond the selected confirmation interval remain refused by the import path. Imported history cannot refresh its policy.

The public app/field shell cache revisions advance to app v2 and field v3 together. The public-only resource whitelist, URL/content-type/redirect guards and online authentication remain unchanged. IndexedDB name/schema, vault format, PBKDF2/AES-GCM custody, packet signing and 24-hour grant/lease/consent/version guards are unchanged. The software continues to use browser custody rather than Android Keystore.

Evidence lives in `tests/evidence/range-protocol/`: 277 focused unit/regression checks and 24 real browser/HTTP checks; typecheck and build pass. The build retains the existing client chunk-size warning. The real Chromium/isolated Worker/D1 harness covers phone publication and capture, receipt replay/authorization, signed population intervals, encrypted offline reload, sync to an unconfirmed draft, stale context and explicit current-patient confirmation, local assistant application, imported source/policy lineage, registration sync, supersession and unchanged prior evidence. Its upgrade fixture seeds previous public-cache namespaces and a real encrypted schema-1 notebook containing a legacy six-unit signed packet before installing the new workers in a fresh browser client. It does not claim an installed prior Android binary or physical-device upgrade. The capture pointer test explicitly focuses Save before clicking to prevent a headless viewport scroll from moving the target during click.

Clinical approval, production population policy activation, physical Android/HTTPS installation/eviction/restart and independent clinical/device accessibility acceptance remain external. Broader CSV import conversion for blood-pressure kPa and gestational weeks+days remains the next required software batch; those existing import columns retain their narrower accepted-unit contract in this batch.
