# Development slice 2i — units and reasoned overrides for unusual measurement values

2 October 2026 (IST). Builds on slices 2c (source and time for each measurement), 2e (author and clinician verification for each measurement) and 7c (pinned outbound FHIR rule set). Synthetic data only; formal acceptance unchanged. BR-DATA-05 stays partial: approved clinical ranges remain outstanding.

## What changed

- **Expected ranges, labelled as a placeholder.** A versioned configuration, `saha-value-ranges-0.1.0`, gives each of the six measurement values Saha captures (systolic and diastolic blood pressure, weight, temperature, gestational age, cough duration) an *expected* range and a wider *confirmation* range in the stored unit. It is labelled "engineering placeholder — not clinically approved" wherever it is shown or written; no clinical authority is claimed and nobody has approved the numbers. It is a code constant in `lib/saha/fact-provenance.ts`: changing it needs a release, and the version is recorded with every override. Organisation & team shows the table (expected range, confirmation range, accepted alternative unit) with that label.
- **Units, stated and converted on the server.** Weight may be entered in pounds (`lb`), temperature in degrees Fahrenheit (`degF`) and cough duration in weeks (`wk`), through a new optional `entered` object in the facts: `{value, unit}` per measurement. The unit is always chosen by the person entering the value; nothing infers a unit from the size of a number. The server converts (lb × 0.45359237 to two decimals of a kilogram; (°F − 32) × 5/9 to one decimal of a degree; weeks × 7 to one decimal of a day), stores the converted value in the usual field and keeps the entered value and unit beside it. A base-unit value sent with an entered one must equal the conversion, otherwise the save is refused ("does not match the entered …; clear one of them"). An unknown unit, a unit for another measurement, a non-numeric or negative entered value, or a conversion below zero is refused. Blood pressure is accepted in mmHg only and gestational age in weeks only (there is no exact conversion from months); height is not captured, so no centimetre/inch handling was needed.
- **Unusual values need a reason.** The shared facts check (`checkFacts`, used by the online save, the field notebook sync through the same save, and field registration) now converts units first and then refuses any value outside its expected range unless the facts carry a reason of at least 10 characters for that measurement (new optional `unusual` object). A reason for a value inside the expected range, or for a blank value, is refused. The assistant's reviewed field application clears the entered unit and reason of each applied field and refuses a proposed value outside the expected range ("Assistant value not applied …"); the worker enters such a value by hand with a reason.
- **Overrides recorded by the server.** After every command, for each visit whose facts changed, the server appends an override record for each unusual value whose value, entered unit or reason changed: the measurement, value and unit, entered value, reason, tier (`reason` or `clinician`), both ranges and the ranges version, the author (the authenticated identity, account code and current role, as in slice 2e; never from the request) and the time. An audit event (`recordUnusualValue`) names the patient, each value, its ranges and the reason. Nothing is ever removed: a changed reason or value appends a new record and the earlier ones stay as history; the record that applies now is the latest one for the current value and reason.
- **Clinician confirmation beyond the wider range.** A value outside the confirmation range also needs a clinician's confirmation before the visit can be confirmed. A new patient command, `confirmUnusualValue` (`visitId`, visit `version`, `field`, `overrideId`, optional note), requires the clinician role and the patient in the clinician's care scope (the slice 2e check), a current draft visit at the stated version, the override that applies now, a value that is beyond the confirmation range, a clinician other than the one who recorded the override, and no earlier confirmation of it. It appends a confirmation (who, account code, when, note), audits it and changes neither the facts nor the visit version, so the recorder's open draft stays current. `confirmVisit` is refused while any unusual value lacks a recorded reason or a required confirmation. Replays recheck role and scope under the current membership (`authorizeFactReview` covers both commands). The command is certified as patient-scoped.
- **Corrections keep the history.** A correction draft starts with the corrected visit's override records and confirmations; an unchanged unusual value keeps its override and confirmation, and a changed one is recorded again and needs a new confirmation. The history names the visit each record was made on.
- **Visit screen.** Capture gains "Other units and unusual values": a unit choice and an entry box for weight, temperature and cough duration (the converted value appears in the usual field; typing in the usual field drops the other-unit entry), and, for each value outside its expected range, a warning with the ranges label and a reason box, with a note when a clinician must confirm it. Saving drops reasons for values that are no longer unusual. The record history and the version-conflict comparison show entered units and reasons as text. Review lists entered units, each current override with its author, reason and confirmation state, a Confirm button for an eligible clinician (a note for the recorder that another clinician must confirm), and earlier overrides as history.
- **Field notebook.** The same controls in English and Hindi (Hindi unreviewed), with the ranges and units mirrored in `public/field/app.js` (a contract check compares the mirror with the server configuration). Before sync the notebook fills the converted base value, drops blank entries and stale reasons, and holds the draft on the device with the server's wording when an unusual value has no reason. The server still decides: it re-checks everything, and a refusal routes the draft to review with the reason, as before. The field registration form does not offer unit or reason controls; the server applies the same checks to it.
- **FHIR.** No resource, element or rule changed. The stored (converted) value is exported as before. Where a value was entered in another unit, the observation note adds "Entered as … ; converted by Saha."; where an override applies, it adds "Unusual value (saha-value-ranges-0.1.0, engineering placeholder — not clinically approved): outside …; reason: …" and, for a value needing confirmation, "Confirmed by … (clinician), time" or "Clinician confirmation pending". Gestational age and cough duration lines in the document narrative add the same text. The FHIR document (EHR publication and mock ABDM transfer) passes the pinned rule set `saha-fhir-r4-document-structure` 1.0.0 unchanged; visits without entered units or overrides produce exactly the earlier output. The FHIR example download adds the same note text.

## Limits

- The ranges are an engineering placeholder. They are not clinically approved, are not age-, sex- or pregnancy-specific (a child's weight and an adult's share one range), and cannot be changed by an organisation without a release. Approved clinical ranges, their governance and per-population ranges remain outstanding for BR-DATA-05.
- Only lb, °F and weeks are accepted as alternative units. Blood pressure (kPa), gestational age (months, weeks + days) and any unit for programme answers are not converted. Conversions round to two decimals of a kilogram and one decimal of a degree or a day; the entered value is kept, so the rounding is visible.
- Overrides cover the six visit measurement values only: programme answers, notes and imported records have no range checks. There is no check that systolic exceeds diastolic.
- A confirmation is a clinician's statement that the unusual value is accepted as recorded; it is not a clinical review, and it is not required for values between the expected and confirmation ranges. Confirmations cannot be withdrawn; a changed value needs a new one.
- The field registration form has no unit or reason controls; a registration with an unusual value is refused by the server and kept for review in the notebook.
- FHIR carries units and overrides as note text only; no extension, `Provenance` resource or coded interpretation is emitted, because the pinned rule set does not permit them. Programme (MIS) payloads carry the stored value without the entered unit or override.
- The notebook keeps its own copy of the ranges and units; a contract check compares them with the server configuration, but a notebook cached before a ranges change keeps the old copy until it reloads (the server decides in any case).
