# Private object-backed visit media and bounded larger online capture

5 October 2026. Author branch starts at `8aa0e967`. B10 / BR-DATA-08 software slice; acceptance remains pending. This document does not reduce the 41-group residual scope or close B11 retention/disposal, clinical image quality or hosted custody approval.

## Product behavior and limits

An explicitly configured private object backend supports JPEG/PNG/WebP and WebM/Ogg/MP3/MP4 visit attachments up to **4 MiB per online item**, with the existing purpose/signature/minimum512-byte rules and ten active items per draft visit. The phone media panel reports that limit, retains reduction to JPEG as the default, and offers an explicit original-file option. Original files retain embedded metadata; selecting this option does not establish clinical quality. Neither signature validation nor successful image rendering makes extracted values confirmed findings. No extraction or clinical decision is added.

The configured switch is `SAHA_MEDIA_STORAGE=r2-private-v1` with the existing private `BUCKET` binding. Default/unset or `d1` keeps the current 256 KiB D1 path. Invalid configuration refuses; it never silently stores a larger body in D1. No binding/secret is enabled in hosting configuration by this change. All author tests use an isolated local bucket, disabled external APIs and synthetic records.

Older small clients without `X-Saha-Expected-Actor` remain on the bounded legacy D1 path, even when object mode is enabled. The new panel supplies this comparison header; it must equal trusted current identity, never supplies identity. The object path requires it. A missing-header large body is refused at the 256 KiB legacy ceiling. Account-bound modern bodies are parsed within the fixed 4 MiB recovery budget; a new default-D1 mutation is still refused above 256 KiB. Saved exact-body receipts remain recoverable after an explicit rollback to D1, with no object access or new clinical mutation. The panel retains exact pending bytes, key and original actor across a transport failure; the original actor must recover the outcome. Bodies/keys are held only in component memory, so this does not add a persisted online queue.

The **encrypted field notebook remains 256 KiB per item, four per draft and its existing 100-item/25 MiB device budget**. Larger offline-field capture is not implemented or inferred from the online change. Its signed capacity, privacy and storage contracts remain intact and this remaining clause stays open.

Uploads are read incrementally within a 30-second body budget, with at most 4 MiB retained. Overlimit input is discarded within a supported limit plus 1 MiB budget, then refused. Early denied/invalid bodies receive a transport-only media-wrapper discard, bounded 5 MiB / 30 seconds, with no parsing, sample storage or clinical retry. A larger hostile body/disconnect may exhaust that transport budget; this is not an unlimited drain guarantee. Export retains its **60 MiB aggregate archive ceiling** and refuses before fetching a media object that would exceed the media-content budget; the existing complete archive-size check remains. This is local functional evidence, not hosted peak-memory/capacity acceptance or O-2 closure.

## Custody, authority and immutable lineage

`0029_object_media.sql` appends nullable `media.storage_ref` and an internal `media_custody` table. Earlier migrations/history are unchanged. A private opaque UUID object key contains no actor, patient, organisation, filename or clinical identifier. The immutable original custody intent binds its initiating trusted actor, request key/input digest, exact patient and visit, byte digest/size/type and timestamp. Conditional create never overwrites an existing key. Metadata HEAD avoids opening an unused object body; one bounded object-body read verifies exact R2 version/ETag, size, SHA-256 and content signature before clinical linking.

A durable reserved-access audit precedes private-object interaction. Current care membership, scope, purpose, draft/evidence, exceptional/restriction/merge and maintenance checks precede writes, are refreshed after reservation, and are repeated after native storage completion. A changed basis refuses rather than silently rebasing. Final visit reference, D1 media metadata, linked custody state, mutation event and command receipt use the existing guarded transaction. Failed/interrupted finalization leaves a staged/quarantined intent; it is never reachable through the playback/export paths. A same-key retry can verify/reuse the original object and finish under current authority. Conditional collisions or changed original bytes refuse; uncertainty does not authorize overwrite. Fifty unresolved intents per original actor/organisation is an atomic finite reservation bound. No automatic cleanup or deletion is supplied.

SQLite triggers prohibit custody deletion, original identity/hash/key/lineage changes, changing a linked object version/ETag, or moving removed/linked state backwards. Draft removal atomically tombstones the clinical media row/reference and moves custody linked→removed; the private object remains retained and inaccessible. Confirmed visits cannot receive or remove attachments. This withdraws access without deciding B11 destruction policy. The operator reconciliation/purge policy for permanently quarantined objects is not approved or implemented here.

Material playback verifies active custody lineage and portable media reference metadata, reads only its exact object version, durably audits before returning bytes, checks current object HEAD and fresh record/member/purpose authority again. Missing/corrupt/changed objects fail closed. No public URL, presigned URL, browser direct bucket fetch, cacheable authenticated media or caller-supplied object key is introduced.

Existing saved media receipt replay was grounded returning200 to a suspended original actor at the baseline. Replay now checks trusted identity, original organisation/patient/visit lineage and current scope/purpose before identifier disclosure, without recreating an attachment/audit mutation or requiring a confirmed visit to become a draft. Legacy/imported receipts with unprovable person lineage fail closed; history is preserved, not rewritten.

Organisation export resolves only already-scoped media rows into verified bytes through the media boundary. Private keys/version storage references and custody intent/request keys are excluded. The archive includes portable media metadata and content with the existing checksum verification; a receiver need not access the private bucket. After durable export audit, each included media row/object and the whole included media patient cohort are checked again; removal or scope withdrawal prevents download. Frozen-report cohort/outcome/receipt visibility and strict standalone verifier code are unchanged. Schema migration metadata advances to0029; private custody exclusion is documented explicitly.
