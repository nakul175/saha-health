## Unknown outcomes, isolation and disclosure

Before the first POST, the client stores `{organisationId,key,body}` in the original-account encrypted notebook using its guarded CAS chain. There are at most20 unresolved preparation references. No background POST or automatic retry/replacement exists. An accepted dropped ACK leaves the original reference; **Check saved preparation outcome** on Today uses only GET and recovers the exact original signed packet. Partial progress means independently saved visits plus explicitly counted unresolved outcomes, never “the whole batch prepared”. An absent outcome remains unknown and its original key is retained. It is not proof that a replacement is safe. Unknown references block destructive notebook deletion.

The accepted packet is verified and checked against fresh online original-account/patient authority before encrypted storage and presentation. A positive changed-account403 locks/hides decrypted work without changing its stored original request. Revocation/reassignment purges the signed packet and embedded descriptors through the existing grant/privacy chain while retaining original tombstones, unknown clinical/media/registration references, historical-open evidence and timing metadata. Expiry and existing per-account grant presentation policies apply. Storage/CAS failure prevents a save acknowledgement and request transmission. Transport failure grants no new access or new packet; it preserves already issued bounded offline access under existing policy.

List/receipt GETs require the original actor comparison and normal care/purpose, record material patient-work access before return, then recompute exact current state. Packet receipt reads additionally validate current original membership/version, assignment/identity, consent, active unexpired lease, original draft/version and prepared task hashes. Audit failure refuses disclosure. A command already accepted before failed response audit remains durably receipted; recovery never recreates its mutation/audit/grant. Returned lists/results use `no-store`. Service workers add only one fixed public JavaScript asset; no authenticated HTML/API/workspace cache is introduced. No schema/migration, object/media/provider or clinical rule changes.
