# Prepared offline programme work — A05

Prepared visits now carry a signed version-1 documentary work descriptor: permitted tasks (`visit-facts`, and `programme-answers` when enrolled), exact captured pack/episode versions and complete existing pack manifests, a digest and clinical-approval-pending label. Maternal, TB and hypertension questions and activated installed-pack questions reuse their existing content. This does not create clinical thresholds or guidance. Preparation refuses more than 20 packs or more than 25 questions in one pack.

The shared `/app` and `/field` encrypted notebook exposes captured pack version, purpose, schedule, escalation text, change note and installed manifest hash. Guidance is a prepared snapshot, never a claim about current online availability. Conditional programme questions, measured facts and explicit absence reasons remain editable offline within the grant. Required-question progress distinguishes recorded/absent answers from incomplete drafts; workers may retain incomplete drafts for online review. Before sync, local validation refuses inactive/unknown answers, invalid options, contradictory absence reasons and oversized answer sets.

Every new server lease retains the original work digest. Sync recomputes it from the server draft's immutable captured packs and checks that each episode remains active at the captured version before saving facts or answers. A supplied client digest must match. Legacy clients may omit that optional field, but cannot bypass the server-held digest or episode checks on a new lease. Older leases without a digest retain their existing identity, membership, consent, assignment, expiry, package-hash and visit-version guards. The client does not select server task authority. Existing append-only audit records include the prepared/synced digest. No migration, route, new command type, external provider or native authentication is added.

Programme answers still sync as an unconfirmed draft through existing server validation and source stamping. Confirmation remains online and requires an explicit current-patient check. Follow-up completion, referral outcomes and governed clinical protocol evaluation/review remain online: the visit grant does not authorize those task types. This batch covers prepared documentary programme questions and guidance, not every action-plan task. Normal episode closure and migration already prohibit altering an episode with an open programme draft; the additional sync guard protects against stale/corrected state.

The packet/vault schema stays 1, with optional additive descriptor metadata. Old encrypted packets and read history stay compatible; no database, key derivation or ciphertext format is reset. Public shell cache names advance together to app v3 and field v4 so the updated controller installs. Only the existing public static resources are cached; patient/pack payloads remain inside the encrypted notebook. Account, reconnect, permission withdrawal and 24-hour grant rules are unchanged. Android continues to use trusted browser custody, not a claimed native Keystore.

Evidence in `tests/evidence/offline-programme/` includes 21 new contract checks and 98 existing field/client/units/shell/app-policy checks. Seventeen real phone Chromium/Worker/D1 checks verify signed guidance, conditional capture and explicit missing reasons, encrypted offline `/app` reload, ciphertext-only IndexedDB, no API cache, descriptor forgery and forbidden task rejection, reachable episode-closure refusal, unconfirmed sync, missing/stale patient-check refusal and revoked-grant refusal. Direct stale episode closure/version and captured-guidance changes are exercised at the contract layer because the normal HTTP commands prohibit closing an episode with an open draft. The phone screenshot records the actual offline rendered journey. Typecheck and build pass; the existing client chunk-size warning remains.
