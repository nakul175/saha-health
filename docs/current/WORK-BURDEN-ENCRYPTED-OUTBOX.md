# Work-burden encrypted outbox contract

This bounded infrastructure batch adds `public/field/burden.js` and a minimal current-care policy read. It does not yet attach the module to field lifecycle, registration, input, save or sync handlers, or cache its resource in either service worker. Those shared hooks wait for the device privacy fix and registration coordination. It does not complete B26 visit attribution or support linkage.

The optional encrypted notebook queue holds at most 200 entries with organisation ID, independent UUID and one fixed capture band or `client-sync-unknown`. Old notebooks need no migration. The current caller supplies the existing serial encrypt/write function and current notebook identity. No new storage, plaintext queue, raw timing, patient facts, clinical body, reason, error, URL or headers are recorded. Signed-grant validity is a required caller predicate, independently from the flag. A positive actor-bound care workspace opts in locally; missing/default-disabled policy creates no queue and no measurement writes. Server policy and counter authority remain authoritative.

Saved capture bands may be queued only after a clinical encrypted save. Unknown sync counts represent an observed unresolved transport transition for a retained pending clinical key, deduplicated within its encrypted draft. Success, replay, conflict, refusal and validation outcomes remain server-produced. This module cannot enqueue those codes. Counts are attributed to the server receipt UTC week, not an inferred offline occurrence time.

A flush seals the queue before transport, checks a current unexpired eligible grant, reads a same-origin minimal policy using manual redirects and refuses login redirects/account mismatches/positive denials. Genuine transport failure leaves the encrypted queue pending. Explicit opt-out removes only measurement metadata without a counter POST. Policy reads require current human ASHA/clinician membership and pin the first resolved organisation; enabled reads are durably audited without patient records and reauthorize after the audit. Disabled policy reads add no measurement/audit/receipt writes. Membership withdrawn during read audit withholds the configuration response. The final event append independently checks fresh server scope/configuration.

Lost acknowledgements retain the exact metadata UUID. The real D1 receipt prevents duplicate count and audit when the encrypted notebook is reloaded and the same event is retried. A clinical command is never issued or retried by the module. A metadata enqueue/write failure must be caught independently by future clinical hooks, not converted into a failed clinical save. Positive device/scope denial must take the existing non-writing lock path before any subsequent persistence. Queue saturation omits measurement; it does not limit clinical work. No samples are transmitted when every relevant prepared grant has expired.

Independent active-stage bands remain different from comparable confirmed completed-visit totals. Required next software: connected field hooks, correction/reconciliation timing, protected receipt/visit/correction-lineage attribution with programme mix, and durable fixed-category support/intervention workflow. External observed pilot savings remain an acceptance boundary.

Validation: 20 module contract checks; 11 actual local Worker/D1 policy checks; 9 real Chromium checks using actual server-signed grant and existing AES-GCM vault APIs. Browser evidence covers encrypted reload, D1 write followed by lost acknowledgement, same-key dedup, no plaintext queue in IndexedDB, wrong-account policy and login redirect denial. Type check and production build pass. These are module/route tests, not an integrated field UI claim or hosted/physical-device acceptance.
