# Delta audit review and saved-receipt replay correction

Independent review of authored delta-audit commit `e934e2ee` as integrated `5fd6ef85` confirmed its new partition branch records the actually permitted returned patients in one access-only batch before disclosure. A fault on the second event rolls back summary and patient-read events while retaining the prior command receipt and visit mutation. Repeated partition disclosures are independently recorded, counts and patient IDs match the actual partition, and read details contain neither patient names nor facts. Current assignment and membership withdrawal refuse receipt disclosure.

## Grounded replay gap

The existing saved-receipt branch reauthorized the command using a whole-organisation load, then used that same state for its response, recording only a workspace summary. It bypassed the normal viewer-scoped/paged material read and its per-patient `auditWindow`. This was an existing branch exposed by the new post-commit read-failure path, not a regression newly introduced by the delta helper.

Actual synthetic Worker/D1 reproduction moved the suite's 501-patient seed **before** the faulted command and retry. A saved-key retry returned 508 full patient records, including 501 never-seen synthetic records, with zero `viewPatientRecord` events. Retaining the original partition-read audit trigger still allowed the retry to return all 508 records. The authored 18-check suite passed despite this gap because its large-scope seed was originally after the saved receipt retry. Aggregate original evidence is retained in `tests/evidence/delta-replay-review/original-replay-disclosure.json`.

## Bounded correction

Saved-receipt reauthorization and result decoding remain intact. Its response now goes through the existing fresh `viewerSnapshot` load, with an optional explicit `replay of a saved command` label. The existing command-response default label is unchanged. This honors current scope and the caller's paging window, invokes established full/window per-record audit semantics before returning content, and then constructs the snapshot from that audited state. It never executes the clinical mutation or replaces its saved receipt.

The expanded actual HTTP/D1 regression passes 26 checks. The care scope exceeds 500 before the first command fault. A retained trigger refusing all per-record reads causes replay to return its existing saved result but omit all unaudited patient and visit records: the established window/full audit contract returns a 200 empty snapshot rather than rerunning the command. After removing the fault, a paged saved-key retry returns and audits exactly its one requested patient; an unpaged retry returns 508 patients whose IDs match durable full-record read events. Summaries carry the replay label and correct actual returned counts. Visit/record versions, organisation/patient revisions and visit count remain unchanged across replay. Existing partition rollback, repeated delta disclosure, audit-detail minimization and assignment/membership withdrawal checks remain enabled.

Read-audit contracts pass 52 checks, scoped reads 27 (105 checks total); build and TypeScript pass. One new regression label query initially searched for a substring at position 1 rather than anywhere inside the summary, and the existing source-shape assertion still expected the old replay branch. Those test issues were corrected without weakening their intended audit requirements; verification notes retain them.

The delta helper was independently reviewed. The replay correction was implemented by this reviewer at the integrator's request, so its final integration needs the integrator's independent rerun. No hosted provider, physical Android, audit coalescing threshold, receipt policy or clinical protocol was changed. Whole-caseload reads below the existing paging threshold retain their established summary policy; this correction does not broaden that policy.
