# Development slice 5a — AI cost budgets and stopping unsent requests

30 September 2026 (IST). Stacked on slice 6j. Synthetic data only; formal acceptance unchanged.

## What changed

- **Monthly budget per capability.** An owner can set or clear a monthly budget in US dollars for any registered AI capability (`opsBudget`: capability key, amount of at least 0.01 or null to clear, reason of 5–500 characters). Budgets are kept in the operations settings, keyed by the capability's stable key, so they survive capability revisions. Setting one is audited with the amount and reason, and the audit line says it is an estimate basis, not an invoice. Administrators see budgets but cannot change them; replayed requests are checked the same way.
- **Estimate.** Spend is estimated from the owner's recorded cost rates (USD per million input and output tokens, the Release 7 `opsRates` setting), for the current UTC month (`lib/saha/ai-budget.ts`): a run with recorded usage costs its tokens at those rates; a run that reached a provider without recorded usage, and an unsent request that has not expired, count at the existing reserved allowance of 6,000 tokens at the higher rate; the local rules-only assistant costs nothing. It is labelled everywhere as an estimate, not an invoice.
- **Refusal before a run.** The existing capability check, which runs before a request is prepared and again before it is sent, now also refuses (429) when the estimated amount used or reserved plus the new request's reservation would exceed the budget. A budget without recorded rates refuses (409), because the cost cannot be estimated. Both messages tell the worker to continue with structured capture and that no provider substitution was made; no other provider or model is ever chosen.
- **Operations page.** Owners and administrators see "AI capability budgets" on the Service & incidents tab: each capability's budget, estimated use, reservations, remaining amount and state (within budget, 80% or more used, reached, no cost rates, no budget, or local with no charge). Owners set and clear budgets there. Supervisors do not receive budget data.
- **Stopping unsent requests.** Only the requesting worker could stop an assistant request. A clinician or supervisor with normal care-team scope for the patient can now stop another worker's request that has not been sent; this releases its reservation. A request already sent to a provider cannot be stopped by someone else, because it cannot be recalled; the requester can still close it. The visit's assistant panel shows "Stop pending request" to clinicians and supervisors on other people's unsent requests.

- 41 contract assertions (`tests/ai-budget-contract.mjs`): cost rules (usage, reservations, expired and cancelled requests, previous month, local); no check without a budget; owner-only setting, unknown capability, nothing to clear, zero amount and stale version refused; audit wording; fail-closed without rates; the request that would exceed the budget refused with nothing recorded; a prepared request counts its own reservation once when sent; cancelling releases a reservation; recorded usage replaces a reservation; the near and reached states; a new amount replaces the old; clearing; stopping another worker's unsent request by a supervisor, refusal for another ASHA, a supervisor outside the team and an administrator, refusal for a sent request, the requester still able to close it; cancellation allowed during maintenance.
- 43 HTTP/D1 assertions (`tests/ai-budget-smoke.mjs`): supervisors receive no budget data; the owner sees the notice and current month; in a new organisation with a draft external capability, supervisor setting refused, unknown capability 404, invalid amount and short reason 422, idempotent replay, "no cost rates" until rates are recorded, then within budget with nothing used; clearing and a second clear refused; a supervisor stops the owner's unsent local request, cannot stop it twice, and cannot stop one already run; the owner can close it.
- `tests/governance-contract.mjs` and `tests/agent-contract.mjs` transpile `governance.ts`, so `ai-budget` was added to their file lists; both pass unchanged.
- Browser check (headless Chromium, built Worker, synthetic owner): the budget table showed "No budget set", the owner set $20.00 with a reason, and the row showed the budget and "No cost rates: requests refused"; axe-core found no WCAG A/AA violations in the budget panel; no console errors. The full accessibility audit (25 screens) still reports none. `tests/evidence/slice-5a/`.

## Limits

- Estimates only: there is no provider invoice, billing API or reconciliation, and no currency other than USD. Rates apply to the whole month as currently recorded.
- Refusal happens before preparing and before sending. A call already in flight when the budget is reached completes; its usage is counted afterwards.
- Evaluations, legacy free-text AI, hosting, storage, MIS and EHR costs are not counted. There are no per-provider, per-deployment or per-task budgets, and no budget alert is delivered (the Operations table shows the state when opened).
- HTTP tests cannot reach the refusal path because live providers are disabled in the sandbox; refusal is covered by the contract suite with a fixture provider.
- BR-AG-07 and BR-AI-12 stay partial: time and retry limits per task, a looping-provider stop that reports completed, cancelled and unresolved actions, invoice reconciliation and validated outage operation remain.
