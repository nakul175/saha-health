# Governed owner calculations for live and immutable reports

This bounded B27 software slice extends the reviewed/effective definition registry with real owner-defined per-person calculations. It does not approve a clinical denominator, official submission, or an external reporting standard. The full [remaining-work ledger](APP-FIRST-REMAINING-WORK.md), including B27/B28/B31 residual work, remains open. The source base is `66d28b8397a65d0bcbf9a31d97eb542bdf00e4dc`; integration, shared test registration, assessment and publication belong to the parent workstream.

## Model and review

An existing primitive string operand remains valid and serializes exactly as before. A new numerator or denominator accepts `{version:1, expression, fixtures}`. Expression leaves name one of the existing sixteen server-controlled per-person measures or a nonnegative constant of at most 1000. Operations are sum, minimum, maximum, any-positive, all-positive and at-least. Any/all/at-least contribute zero or one per person; they do not test an aggregate total. Variadic operations have two to four terms. An expression has at most 31 nodes and five levels, includes at least one primitive leaf and one operation, and produces safe nonnegative integers no greater than 100000 per person. Thresholds are integers from 1 to 100000. Overflow refuses a query before cells are returned.

The model refuses free fields, patient identifiers, notes, measurements, arbitrary code, SQL, references to other definitions, unsupported model versions, subtraction and other unsupported conversions. These limits are an explicit computation contract, not an assertion that every possible measure formula exists. New expression proportions also refuse any current person whose numerator exceeds their denominator. Existing primitive-only proportion behavior remains intact.

Each operand requires two to six distinct owner-supplied input examples. Every example names all and only the expression's primitive leaves and supplies an independently entered expected contribution. The server evaluates the actual expression and refuses mismatches, missing inputs, duplicates or out-of-range values. Examples are governed mathematical fixtures, not patient facts or clinical approval. The phone builder starts an unsubmitted template; no definition or clinical default is generated or published automatically. Owners select operations and measures and enter expected results. Independent reviewers see the full human-readable calculation and its versioned inputs/expected results.

The original immutable proposal/review/future-effective release/current reviewer authority/withdrawal/revision/rollback machinery is reused. A new version appends its complete model and fixtures; rollback copies a released source model into a new proposal requiring fresh independent review. A clinician reviewing definition metadata obtains no aggregate reporting permission. Unknown mutation outcomes retain the original body/key for lookup; the actual phone lost-acknowledgement check demonstrates this within the existing tab recovery boundary.

## Privacy: actual dependencies, profiles and zero contributors

Each expression adds conservative protected primitive dependency candidates with the same definition identity, current filters, exclusions, grouping, window and actual per-person source values. Small primitive cells suppress the combined result even when constants or other terms make its total large. A refused dependency withholds the whole expression. These candidates pass through the existing live, CSV, destination and frozen/edition release guards and CAS storage path. No raw per-person contribution values appear in metadata or disclosure audit.

Primitive dependencies alone were insufficient: the actual Worker released all=5 and any=6 after one supported clinical void, exposing a one-person complement. The preserved [before report](../../tests/evidence/composite-measures/before/boolean-complement.json) and hash-verified source preimages are diagnostic evidence with zero accepted assertions. The added expression profile guard therefore computes actual joint per-person contributions across all disclosed operands whenever an expression participates. It refuses newly involved profiles or splits represented by one to four people. It works with current and frozen populations and compares different expressions as well as their dependencies. Primitive-only queries retain the legacy path.

A second actual destination probe exposed threshold=6→5 because the first guard treated a candidate zero contribution as absence. Its [complete original/current payloads and source hashes](../../tests/evidence/composite-measures/before/destination-zero-complement.json) remain unchanged. The repaired guard counts in-scope candidate cell membership, including zero contributions, and retains zero-valued in-scope profiles. The repeated sensitive destination preparation now refuses the whole report atomically; original payload and manifest bytes remain unchanged.

This protection is deliberately conservative: an expression can be withheld even when its aggregate exceeds five or an unchanged expression output has a sensitive underlying dependency. Accepted conservative dependency evidence may constrain later queries. Existing seven-day live ledger boundaries, durable edition checks, ledger capacity refusal and broader B28 cross-viewer/collusion/operating-policy limits remain; this slice does not assert that independent people cannot combine previously copied reports. Two independent viewer accounts were each challenged with simultaneous incompatible edition requests: only one safe edition was released per account, and conflicting requests returned 409. Original publication was never rewritten.
