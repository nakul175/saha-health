# Encrypted registration and match-copy privacy

5 October 2026. Synthetic software contract; hosted privacy, real-user and physical device acceptance remain pending.

Registration cleanup extends the prepared-visit privacy contract without changing the schema-1 browser-owned vault. A first accepted `registerFieldPerson` command atomically records original trusted actor/organisation/registration identity, actual accepted receipt key and body digest, original membership version/role, patient version, consent version, identity digest and server issuance time. Repeating a registration ID under another key adds an exact accepted receipt binding and never renews that original baseline. Migration `0022_registration_device_work` adds registration grants, accepted receipt mappings and protected match-copy provenance; no earlier migration is changed.

The privacy endpoint permits strict metadata-only `registration-owner`, `registration-reconcile` and `registration-ack` commands. The owner response contains only the actual trusted authenticated user ID and gives no organisation or patient authority. Reconciliation takes registration IDs and exact own operation key/body digests, or protected match copy IDs. It rejects client patient pointers, raw names/query text, headers, URLs and arbitrary diagnostic details. Own accepted receipts bind the actual stored registration identity and original actor; an absent receipt remains unknown. A receipt cannot authorize another actor, organisation, registration or digest. The current command-type provenance, when available, must also identify `registerFieldPerson`.

Legacy bootstrap requires a real accepted own receipt and matching stored original registration identity. Missing original membership/role/patient version/consent/identity history remains null rather than being inferred from today's records. Legacy accepted copies receive a review-required purge instruction so fresh online care is required. New copies compare the immutable issuance baseline against current consent, identity, assignment/access, restrictions and membership. Original actor metadata ownership after removal allows only redacted instructions, own receipt outcomes and acknowledgements; it never restores patient reads or care commands. Instructions and receipts append with the existing chained audit and guarded database commit; current patient and membership snapshots prevent stale permission instructions from committing.

An unsent registration or local form has no server patient grant. Its arbitrary client ID cannot authorize a patient lookup or consent-derived deletion. A positive trusted original actor's own historical organisation membership removal/non-care status can instruct deletion of that actor's org-bound local-only registrations, form and context. Unknown organisation/identity fails closed and retains encrypted proof. Unsent drafts under a currently permitted care membership remain local-only captures; this contract does not invent patient consent history for them.

A normal scoped and audited patient-match search now issues protected provenance for exactly the returned candidate IDs/versions, query hash, original membership version/role and issuance time. No raw query is stored in that metadata registry. Current candidate scope and versions are revalidated by opaque receipt ID. Copied match names, ages, locality and draft review text are discarded before any connected clinical/ref check: a fixed metadata-free privacy latch is set, the trusted owner is checked, and an encrypted revision-checked preflight removes those cached details. Wrong account never changes ciphertext. Transport or preflight-write failure keeps the notebook locked; the latch prevents offline redisplay until connected validation and cleanup complete. If latch storage fails, the UI explicitly warns and claims only current-tab locking. Protected candidate references are checked in batches of at most ten; registration references are checked in batches of at most twenty, preserving existing notebook capacities. A fresh normal authorized search is required before match facts are reused; existing final review decisions/history remain subject to the server's freshness validation.

Before registration dispatch the notebook durably retains each exact operation key/body digest. Known success marks its reference accepted; refusal or lost response never erases uncertain prior references or permits a blind resend. Reset/discard refuses uncertain references. Purge writes encrypted removal and minimal receipt tombstones in one revision-checked transaction before acknowledgement, preserving keys/digests/outcomes and stable acknowledgement IDs without registration facts, original command bodies or candidate names. Later metadata checks can change unknown outcomes to accepted; accepted evidence is never downgraded. Partial cleanup survives a later failure because the failure lock clears plaintext without persisting a stale book. The reachable privacy acknowledgement control includes both prepared and registration tombstones.

Each encrypted registration form has an opaque UUID. Explicit queueing reuses it as the registration ID; legacy forms without it generate a new ID. This provides exact later accepted-receipt correlation for client material-open work without asserting server authority for a purely local unsent form. Unrelated encrypted notebook fields survive cloning and cleanup, so pending protected telemetry/material metadata can be integrated independently. Public-only caches move to app v6/field v7 with the new static module; no authenticated HTML/API or patient plaintext is cached. There is no native Keystore or verified flash-erasure claim.
