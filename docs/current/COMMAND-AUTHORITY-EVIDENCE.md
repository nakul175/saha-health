# Append-only command authority evidence

5 October 2026. B04 software clause based on integration `a52ca6e0`. New command audit events now carry a `saha-command-authority-v1` JSON suffix before the existing audit-chain hash is calculated. No migration or new runtime module is added, and previous audit history is not rewritten.

## Recorded meaning and interfaces

`store.persist` decorates only its new non-`ACCESS_AUDIT` audit rows (including extra command audit rows). The initiating identity is the event's actual server-generated actor id, which can differ from the receipt actor. Membership role, status, version and owner flag come from `before.members`, the pre-mutation state. A self-edit cannot replace its own initiating membership evidence with its new authority. The existing detail stays verbatim before the suffix; no names, reasons, clinical facts or client identity fields are copied into the envelope.

Server-generated `role=system` events are explicitly system/non-membership execution. Other events with no matching pre-mutation membership are explicitly non-member. Joining an organisation records the absence/inactive state of prior membership rather than claiming the new membership authorized its own creation. `createState` decorates only its newly created baseline event with a distinct bootstrap membership source; legacy/imported audit rows remain verbatim. Membership absence is evidence, not a permission grant. Existing current membership, patient-scope, version and transaction guards still decide whether a command may commit.

`delegationAudit` now returns a copy of actual `delegationUsed` entries before deleting the transient list. The dispatcher passes that server-derived list through optional internal persist metadata. Each use records id, kind, grantor id and expiry, without the free-text grant reason. Uses attach only to their initiating actor, not unrelated/system events in the same batch. Direct callers can supply their own server-held actual-use list or transient marker; without either, the envelope explicitly says `not-tracked`, rather than claiming no delegation existed. Client-supplied extra fields cannot substitute for the server-created metadata; the actual route test verifies the existing schema discards such extras.

Operations CSV supplies an optional `recordExportAudit` callback after current export authorization. It recomputes the current authorized reporting reach on every commit attempt, preserving existing `sameReach` and care-scope checks. Delegated-only reporting captures its exact selected grants; a grant already covered entirely by the viewer's own patient scope is not attributed as widening authority. A grant with patients outside own scope is recorded even when its teams overlap own teams. Own-scope/support exports provide an explicit empty use list. This metadata is about the chosen current reporting reach, not proof that every overlapping grant was logically necessary for each exported cell.

The suffix is the final `\nCommand authority: ` marker followed by JSON. Consumers must read the final marker, not the first: original user-authored detail may contain similar text. The unit test preserves such original text while parsing the final server-owned envelope. Hash verification includes the whole detail, including the suffix.

## Covered and excluded writers

The common persist boundary covers human command dispatch, media commits, agent/EHR/MIS/evaluation/destination/aggregate/independent-provider checkpoints, export commits, scheduled caseload/timeouts and mock reminder opt-outs. Provider-keyed reminder receipts are distinct from actual event initiation: staff simulation records the staff membership, while a signed mock callback records a non-member provider event.

Access-only writes retain their existing read authority clause. Direct operational writers (`persistScheduledRecord`, availability samples, notification side-table access writes) retain their existing system/read semantics and are excluded from this command envelope. Held grants are not relabelled as used grants. Callers with untracked uses remain explicitly unknown/not-tracked; broader provenance/acceptance remains separate work.

## Replay and remaining distinction

Saved receipt replay bypasses mutation persistence and creates no new command envelope. Existing current identity/membership/patient checks still govern disclosure. The actual assignment test distinguishes revoking permission to make a new assignment (fresh command 403) from reading an already saved receipt while the clinician still has patient scope (same-key replay 200, no new mutation/event). Removing patient scope or membership returns 403 on saved receipt read. This batch preserves that distinction; it does not certify the whole replay-authority inventory. The independently discovered replay per-record read-audit repair is integrated separately; root reruns its actual Worker/D1 regression on the combined source. See [replay review](DELTA-REPLAY-INDEPENDENT-REVIEW.md).
