## User / outcome

As a permitted integration user, I need to use an owner-authorised file or document hand-off when the approved structured route is unavailable, so that I can track its limitations and receipt without mistaking preparation for destination acceptance.

Bounded scope: Preserve reconciliation IDs, original artefacts, extraction review and batch delay; unsupported writeback remains unavailable, and credentials or restrictions are never bypassed.

## Original requirement and acceptance text

### BR-INT-08 — Limited integration alternatives

Priority: Must; original release: R1.

Where approved APIs are unavailable, owner-authorised file exchange or assisted submission may be supported and labelled as such. Credentials, access controls or usage restrictions shall not be bypassed to simulate connectivity.

Acceptance: Exported files carry reconciliation identifiers; a prepared export is never reported as accepted until acceptance evidence is recorded.

### BR-INT-22 — Legacy and document exchange

Priority: Should; original release: R1.

Where FHIR is unavailable, the platform may use authorised HL7 v2, CDA, REST, SOAP, file or document exchange. The connector shall label the resulting limitations, preserve the original artefact and avoid presenting batch preparation or document extraction as real-time structured acceptance.

Acceptance: A batch or document connector identifies its delay, source document, extracted fields, reviewer and destination receipt; unsupported writeback remains unavailable.
