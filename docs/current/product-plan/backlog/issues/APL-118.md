## User / outcome

As a frontline worker reconnecting after an outage, I need to synchronise dependent person, encounter and referral records in valid order with stable command IDs, so that intermittent connectivity cannot create orphan records or replay successful actions.

Bounded scope: Return per-item results and permission checks; preserve the source's 200-record queue, 95 percent eligible structured arrival within 5 minutes target under reference conditions, with media/external acceptance measured separately.

## Original requirement and acceptance text

### BR-OFF-05 — Safe synchronisation ordering

Priority: Must; original release: R1.

Dependent records shall synchronise in a valid order, preserving identities and stable submission identifiers. The application shall recover from intermittent connectivity without replaying successful actions.

Acceptance: A new local person, encounter and referral synchronise without orphan records across repeated connection loss and restoration.

### NFR-12 — Synchronisation recovery

Priority: Must; original release: R1.

On stable reconnection, 95 percent of eligible structured records in a 200-record queue shall reach the platform within 5 minutes under reference network conditions. Media and external destination acceptance have separate measures.

Verification: Queue tests measure completion, rejected records, permission rechecks and remaining unresolved items.

## Additional CWO acceptance / refusal criteria

* **CWO-006-AC01 (New acceptance)**: Given a local completed capture, reconnection produces one corresponding server record or one explicit unresolved state, without requesting the worker to recapture the data.
