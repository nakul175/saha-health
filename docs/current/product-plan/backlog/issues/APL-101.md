## User / outcome

As an integration owner, I need to check mapping and connector upgrades against queued work, receipts, amendments and historical records, so that a breaking schema change pauses affected work without corrupting data or inventing missing values.

Bounded scope: Owner review and regression evidence govern activation; in-flight work finishes on a compatible version or enters controlled review, while unaffected workflows continue.

## Original requirement and acceptance text

### BR-INT-07 — Schema and mapping change control

Priority: Must; original release: R1.

External form, code or API changes shall trigger compatibility checks and owner review. Failed validation shall pause affected submissions while preserving queued data and unaffected workflows.

Acceptance: A removed mandatory destination field causes a controlled connector exception, not silent data loss or guessed replacement values.

### NFR-27 — Connector upgrade compatibility

Priority: Must; original release: R1.

A connector or FHIR package upgrade shall pass regression tests for existing mappings, queued actions, receipts, amendments and historical display before activation. In-flight work shall finish on its compatible version or enter controlled review.

Acceptance: Verification: A simulated breaking version change does not corrupt queued work or silently reinterpret historical records.
