Inspect the existing synthetic release manifest, the distinct Cloudflare/DigitalOcean mechanisms and the exact served source/build identity through authorised access. Produce a release/recovery evidence matrix for all eleven CWO-008 clauses: identity match, failed build/health retention, migration state, compatible rollback and protected persistent records/queues. Keep merge, process start, healthy serving and observed live identity separate. Read-only hosting evidence does not authorise a recovery mutation or prove production readiness; record missing access or rehearsal authority as a blocker.

## Source and owned criteria

Parent: SAHA-152; source CWO references: CWO-008; decision references: DEC-07. This task is derived from existing reconciled CWO scope, not a new BRD requirement. No estimate, release date, named executor or institutional policy is invented.

* **CWO-008-AC01 (New acceptance)**: For a rehearsal deployment, the reported served source/build identity matches the release manifest rather than simply the newest main SHA.
* **CWO-008-AC02 (New acceptance)**: A failed build or failed new-release health check does not replace a previously serving qualified synthetic copy.
* **CWO-008-AC03 (New acceptance)**: An interrupted migration rehearsal has a declared observable recovery state; it does not mark an unapplied or partly applied migration as successfully applied.
* **CWO-008-AC04 (New acceptance)**: A code rollback is allowed only when schema/queue compatibility has been checked, with recovery evidence attached.
* **CWO-008-AC05 (New acceptance)**: The plan identifies and separately controls the Cloudflare and DigitalOcean deployment mechanisms.
* **CWO-008-NEG01 (Expected refusal / recovery)**: Missing release evidence or a mismatched build digest blocks promotion.
* **CWO-008-NEG02 (Expected refusal / recovery)**: A migration whose data compatibility is unknown is not silently rolled back by switching the source tree.
* **CWO-008-NEG03 (Expected refusal / recovery)**: Unavailable host access produces a not-inspected status, not a simulated claim that the live host was checked.
* **CWO-008-RJ01 (Delivery rejection)**: Reject any deployment claim produced only from reading deploy/README.md.
* **CWO-008-RJ02 (Delivery rejection)**: Reject exposure of secrets or a release process that overwrites persistent data.
* **CWO-008-RJ03 (Delivery rejection)**: Reject presenting this development-runtime deployment as production-ready.
