## User / outcome

As a previously authorised frontline worker, I need to use my limited encrypted caseload, valid cached guidance and permitted capture/tasks during an outage, so that I can continue the approved offline visit while seeing remote-only functions as pending or unavailable.

Bounded scope: Qualify the scoped offline manifest and lease; cloud-only AI must never be shown as having run or return a fabricated result.

## Original requirement and acceptance text

### BR-OFF-01 — Defined offline capability

Priority: Must; original release: R1.

Previously authorised users shall be able to access a limited encrypted caseload, capture encounters, review valid cached guidance and prepare tasks during outages. Functions needing remote information or models shall show their unavailable or pending state.

Acceptance: The core offline visit test completes without network access; no cloud model is falsely shown as having run.

## Additional CWO acceptance / refusal criteria

* **CWO-005-AC01 (New acceptance)**: Given previously prepared permitted work, airplane mode does not prevent completing manual capture and obtaining a local-save receipt.
* **CWO-005-RJ01 (Delivery rejection)**: Reject any implementation requiring a new online sign-off merely to finish normal manual capture that the existing process permits.
* **CWO-005-RJ03 (Delivery rejection)**: Reject unreviewed weakening of encryption or silently dropping queued media.
