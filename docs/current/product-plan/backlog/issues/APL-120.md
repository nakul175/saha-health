## User / outcome

As a frontline worker sharing or reporting a lost device, I need to lock and isolate my cached records and decrypted state, so that another user cannot see them and a lost device loses server access at its next contact.

Bounded scope: Cover user switching, sensitive notification hiding, encryption and offline grant expiry; remote revocation/wipe limits remain visible when the device is disconnected.

## Original requirement and acceptance text

### BR-OFF-07 — Shared and lost devices

Priority: Must; original release: R1.

The application shall isolate local user data, hide sensitive notifications, support quick locking and allow remote revocation when connectivity returns. Local encryption and grant expiry shall protect offline data where remote wiping cannot be guaranteed.

Acceptance: A second user cannot view the first user's cached records, and a reported lost device loses server access on its next contact.

## Additional CWO acceptance / refusal criteria

* **CWO-005-NEG03 (Expected refusal / recovery)**: Another account cannot decrypt or display the first worker’s drafts merely by opening the same phone shell.
