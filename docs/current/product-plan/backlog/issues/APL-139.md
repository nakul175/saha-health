## User / outcome

As an authorised configuration publisher, I want packs, language content, knowledge, model versions and mappings to move through reviewed, approved, published and reversible versions, so failed changes can be rolled back while preserving the history of affected work.

**Scope boundary:** Sensitive changes require independent approval and an impact summary. Use documented configuration paths rather than ad hoc database edits or undocumented production scripts.

## Original requirement and acceptance text

### BR-OPS-03 — Controlled publishing and rollback

Priority: Must; original release: R1.

Programme packs, language content, knowledge sources, model versions and mappings shall use review, approval, publication and rollback states. Sensitive changes require independent approval and an impact summary.

Acceptance: A failed change is reversible to an approved version while preserving the history of work completed under the changed version.

### NFR-19 — Maintainable configuration

Priority: Must; original release: R1.

Common content, language, indicator and workflow changes shall follow versioned configuration paths where possible. They shall not require ad hoc database edits or undocumented production scripts.

Verification: A programme change is reviewed, tested, deployed and rolled back through the documented operating process.
