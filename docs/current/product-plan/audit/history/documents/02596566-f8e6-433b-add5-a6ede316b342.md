## Readiness checklist for one bounded task

Before Todo, record the permitted actor, the trigger, the user/operator goal and the observable value; identify the exact canonical owner and criteria subset. Inspect and name current reuse/API/record/version/audit behaviour, included/excluded UX states and applicable unchanged NFR targets. Freeze a synthetic fixture and expected positive, refusal, invalid-input, unavailable-dependency and recovery results wherever applicable. For each case, state the precondition, action, observable result and prohibited side effects. Record required authority, source, device, host or external inputs and the precise resume evidence if missing.

A design dependency or related scope link is not evidence that its whole parent is accepted. Use a native completion dependency when a specific prior task output is actually required; otherwise record the inspected reusable component and its unverified boundary. A bounded task must not quietly replace a whole canonical requirement. Separate original acceptance clauses, proposed refinement criteria and frozen implementation criteria so their authority is visible.

## Definition of done

Implemented on an isolated published branch; actual affected tests and adverse paths pass on named source/configuration; failures retained; no weakened targets/assertions; final-head CI and separate diff/evidence review; required native approvals/protections satisfied; existing story-specific release authority; merge and observed deployment recorded separately; live authorised synthetic story smoke passes when part of its gate.
A technical-task completion never implies its whole story or parent requirement has passed. Product, clinical, ASHA, physical-device, government and formal UAT acceptance are separate.

## States and holds

Backlog: queued, unknown or prerequisite-held.
Todo: execution-ready after explicit readiness checks.
In Progress: existing candidate work, with a written hold reason if paused.
In Review: a published frozen candidate is actually under review.
Done: the stated item boundary has evidence; story Done requires its whole delivery gate.
Use explicit blocker/resume-condition text and dependency relations; do not mark a story Done to remove a blocker. Parent epics are non-dispatch containers.
