## Working rules

One active implementation. Every story retains original scope IDs, canonical frozen criteria, dependencies and evidence links. Re-read current source before work. Do not use historical candidate results to qualify different code. Existing Done means bounded delivered engineering scope only; formal, clinical, ASHA and physical-phone acceptance remain separate.

Use existing statuses: Backlog for unspecified/queued work, Todo only after readiness and dependencies are checked, In Progress for actual work, In Review for an actual frozen candidate under review, Done only with declared completion evidence. Record blockers explicitly in descriptions. Do not invent a release from issue closure.

## Story preparation template

User/need/outcome; original scope IDs; included/excluded behaviour; frozen versioned acceptance criteria; inspected reuse points; data/API and UX implications; dependencies; exact test plan; release/recovery boundaries; code/spec/evidence links. Technical subtasks derive from the story; they do not replace the user outcome.

## Automation ownership

Planning/status reconciliation may read GitHub and update mapped Linear records and this project's status. It never starts a competing coding run, edits code, changes acceptance criteria, closes source issues, merges, deploys, changes credentials, or restarts disabled schedules.
