# Governed inbound clinical version conflicts

5 October 2026. B09 software author batch, based on published a40810fb; formal BR-DATA-07/BR-INT-06/BR-INT-21 acceptance is not promoted by this document.

The existing EHR file importer refuses same-identifier/different-content with409 without retaining the second document. Existing R27 handles correction/identity obligations, and EHR receipt resolution handles zero/one/many identifier matches; neither is a clinical version decision. The retained baseline contract and actual existing-import409 observation are in tests/evidence/inbound-conflicts.

## Working product boundary

The patient Record tools contains **Inbound clinical conflicts**, reachable in `/app` and the browser demonstration. An authorised care clinician/supervisor stages a changed FHIR document against an original stored document and a current local visit or explicit amendment draft, chooses an assigned clinician and declares source versions and effective time. A version token present in either original document must agree with its declaration. Identical content or different document identifiers refuse; repeated exact open versions refuse, but an explicitly restaged comparison after local changes retains the old evidence and creates a fresh review.

Each patient has at most40 conflict records. Each record retains exact original and incoming bundles, hashes/structural summaries, source version tokens/effective time, the complete local Visit when staged, optional original accepted operation/receipt snapshot, assignment history (50), and one immutable final decision. These are optional EhrState/Visit JSON extensions in existing storage; there is no migration or rewrite of old EHR documents, approved bodies, receipts, or confirmed history.

The assigned current scoped clinician must differ from the initiating actor. They can keep local work, retain the incoming version as a source reference, or explicitly choose local/incoming for each mapped supported observation (blood pressure, weight, temperature) into a current draft. There is no inferred field choice, duplicate-observation selection, note replacement, default last-write-wins, enrolment, automatic confirmation or clinical verification. An incoming selection is reported with its original observation time and trusted clinician author. Existing conversion metadata and unusual-value reasons are cleared for changed incoming fields; a value needing a new reason must be handled through ordinary capture/review rather than reuse an old exception. Ordinary pinned range context and core saveVisit validation still apply; future-effective sources cannot change a draft. The draft records exact source/decision lineage. Earlier local facts, source bytes and decision before/after canonical visit-content hashes (saha-inbound-visit-v1, recursively sorted object keys, exact persisted revision/lineage) remain available. Existing raw document/approval hashes are unchanged.

Accepted-destination conflicts additionally require an actual locally stored accepted operation with receipt, exact original bundle hash/body, same patient/link and original visit (or its explicit amendment draft). The queue preserves the accepted operation, original confirmed body and downstream correction tasks. Its merge changes only the explicit local draft. No remote accepted record is overwritten, receipt state reopened, conditional amendment sent, provider enabled or unknown delivery retried. Existing EHR amendment publication remains unavailable (B22), so a resolved local comparison does not claim completed downstream reconciliation.

## Authority, reads and recovery

`/api/inbound-conflicts` GET accepts exactly one personId; POST has a strict fixed action schema with UUID retry key and expected original actor. Trusted identity is resolved before body parsing; actor equality is a refusal checkpoint, never public authority. Current normal team/facility/programme patient scope, active clinician/supervisor role, care-coordination purpose and identity/restriction gates apply. Owners and exceptional grants cannot widen access. Assignment and decisions require a currently scoped assigned clinician; saved receipts retain current patient/role/purpose and participant checks and do not manufacture another event or clinical edit.

A decision pins the entire current local visit (including correction and pending plan), linked identity, exchange consent revision, original/current source bytes/summary, exact connection version, permission, source versions/effective time and accepted operation where relevant. Stale work rejects409 and preserves the local work; fetching a new view does not waive the original comparison. Suspended member or withdrawn patient/purpose scope refuses403. Positive reads append patient history access before material disclosure, pin the resolved organisation, reload fresh scope and compare record/actor state. Historical source evidence remains readable in current normal patient scope when exchange/reviewer eligibility has ended, but the row is blocked/stale for new decisions. No identifiers, notes, clinical values or source bodies enter read telemetry detail.

Mutations use the existing whole-organisation guarded persist transaction: clinical draft/retained ledger/audit chain/receipt either commit together or roll back. Supported membership/config/patient concurrent commands move existing authority/revision guards. This route is **not partition certified** and does not claim an independent generic SQL mutation-authority rewrite. Response bodies after writes contain identifiers/status only, not patient facts. A failed read audit or uncertain transport does not replay a clinical mutation; the exact original key/body can recover a saved outcome after current authority checks. The UI retains a key for an exact body during its mounted session; it does not persist plaintext bodies or implement a reload-safe clinical outbox. Inspect history after a lost response; do not blindly create a new action.

## Limits and acceptance still pending

The intake is a bounded12000-character documentary FHIR structural subset, with an existing confirmed link and local permission. Its source origin is honestly file. Declared versions/effective times and a local accepted receipt are not authenticated partner provenance, issuer approval, full FHIR/ABDM conformance or demonstrated destination version support. The accepted-operation HTTP witness uses an explicitly labelled persisted synthetic accepted-record fixture; no partner acceptance occurred. Automatic retrieveEhrDocument→stageDocument changed-response handoff remains a BUILD follow-on, not an external-only acceptance item. No inbound network callback, scheduled receipt processing, native offline two-device qualification or external amendment/correction acceptance is claimed. These remain separate full-product interfaces/qualification; B09 is not marked wholly complete by this bounded software batch.

Author evidence and exact counts are retained in tests/evidence/inbound-conflicts. New route/suites need root's shared catalogue/security inventory integration. Shared changes are only optional EhrState.inboundConflicts, Visit.inboundSourceDecisions and the workspace import/mount; all other modules are dedicated.
