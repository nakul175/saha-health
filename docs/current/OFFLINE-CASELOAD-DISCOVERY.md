## Proposed bounded author scope, subject to exclusive ownership approval

1. **Discover current eligible work online.** A dedicated strict-query care route returns a bounded page (20 patients maximum) of the originating worker's normally permitted assigned patients and actual open work references. Initial task vocabulary is existing open worker-owned follow-ups, including installed-work-generated follow-ups only when their protected original occurrence/source remains current. Referrals/escalations may be displayed as explicit read-only current work if exact scope/source provenance can be validated; they are never silently converted into follow-up completion. No invented due default, hidden prioritisation, model run, guessed diagnosis or completion policy. `moreAvailable`/page freshness is explicit; a list page is not the whole cohort. Reuse the normal work-list ordering and source contracts without copying an entire workspace. Durable material patient-work read audit precedes disclosure, followed by exact membership/purpose/source recomputation.
2. **Prepare only deliberately selected work.** A small explicit preparation request binds the original expected actor, resolved org, current patient versions, selected source IDs/version hashes and list basis. Server identity is trusted; supplied actor is comparison only. Limit 20 patients, one packet per patient, bounded total payload, and strict idempotency key/body. The server reuses `applyField` signing/24-hour leases and exact programme/range captures for each selected encounter; the normal common transaction records all packets/grants or none. No confirmation, clinical decision, outbound action, completion or enrollment occurs. Existing current local draft must be reopened/compared rather than silently replaced. UI can prepare one chosen patient at a time from the reviewed list, or a reviewed selected group only if separately approved; arbitrary whole-workspace prefetch is excluded.
3. **Add signed source work descriptors to each individual packet.** Source task IDs/kind, owner, due UTC/date, state, source visit/version/hash, installed pack/manifest/version and patient version are included only when applicable and server-derived. Existing manual follow-up title/due remain explicit source text, not an inferred recommendation. Original packet signature/packageHash binds the descriptor. Encrypted Today groups the selected packets and shows due task/source/expiry states; it does not reconstruct an online workspace. No standalone patient descriptor may outlive its own grant. Missing/legacy descriptors mean “prepared visit only / tasks not prepared”, not clean/current task coverage.
4. **Preserve account, expiry and purge boundaries.** The originating book/account, exact per-patient grant/package, membership, identity/assignment, consent, care purpose, record version and programme/source versions remain authoritative. Online positive denial locks/redacts first; transport failure permits only unexpired signed material. Current source/pack changes require explicit online review/reprepare; they never silently rebase clinical work. Reconcile per existing durable grant metadata, remove descriptors with revoked packet copies using the guarded encrypted CAS chain, preserve all unknown clinical keys/body hashes/media/deletion/registration/historical presentation/timing queues. Visibility checks are before exposure on both `/app/offline/` and `/field/`; signed expiry hides both identity and work. Existing historical-open report and purge ACK original-account rules remain intact.
5. **Only documentary capture is writable offline.** Selecting an already prepared task opens its signed encounter. Save remains encrypted-only until acknowledgement; Sync uploads the existing unconfirmed documentary draft. Review/confirm, task completion, escalation resolution, referral events, provider lookups/messages and installed transition approval stay online with current authority. UI uses one selected patient/task at a time with explicit Prepare, Save on device, Sync and Online review choices. Completion is not inferred from visit capture or sync success.
