# Development slice r21 — coded FHIR provenance and structured (non-note) overrides

3 October 2026 (IST). Builds on slices 2c (source and time for each measurement), 2e (author and clinician verification per measurement), 2g (note/answer authors and supervisor sign-off), 2i (units and reasoned overrides), 10g (disputes and sign-off rules) and 7c (pinned outbound FHIR rule set). Synthetic data only; formal acceptance unchanged. BR-DATA-02, BR-DATA-05 and BR-INT-11 stay partial: coded provenance and structured overrides are emitted, but they are not yet profiled by an HL7 validator, terminology server or the NRCeS package, and no external terminology is claimed.

## What changed

- **A `Provenance` resource per recorded observation.** The FHIR document builder (`lib/saha/fhir-document.ts`) now emits, for each exported measurement observation, a FHIR R4 `Provenance` resource whose `target` is that observation. Its agents reflect the server-recorded identity: the measurement author (`factAuthors[measure]`, the same Practitioner that is already the observation's `performer`) as an `author`, and the latest clinician review (`factReviews`, slice 2e) as a `verifier` carrying the coded verification state (`verified` or `disputed`) and, for a dispute, the reason. Each agent also carries its recorded time. Nothing is taken from the request: only the visit record's stored authors and reviews are reflected.
- **A visit-level `Provenance` for the supervisor sign-off.** When the visit has a current sign-off (slice 2g/10g — the latest sign-off matching the confirmed visit version and not withdrawn), the document adds one more `Provenance` whose `target` is the Composition, with the sign-off as an `attester` agent carrying the supervisor's role and recorded time. A withdrawn or stale sign-off is not emitted.
- **A structured (non-note) override extension.** For each measurement whose value was entered in another unit or is outside the expected range, the observation now carries an extension `urn:saha:fhir:unusual-value` with sub-elements for the entered value and unit, the reason, the tier (`reason` or `clinician`), the ranges version and expected/confirmation ranges, the recorder (name and role) and recorded time, and, when the value needed a clinician's confirmation (slice 2i), the confirmer and time (and note). The free-text observation notes are unchanged, so existing consumers and the earlier note-based output keep working; the override is now also present as machine-readable structure (BR-DATA-05).
- **The pinned rule set.** `saha-fhir-r4-document-structure` keeps its id and `fhirVersion` `4.0.1`, and the 14-case regression corpus in `tests/fhir-validate-contract.mjs` still passes. The structural subset now additionally *permits* the `Provenance` resource type. As built, the slice kept version `1.0.0`; the integration of #144 (review finding) moved it to `1.1.0` and names Provenance in the basis text, because a rule set that accepts documents its earlier version refused must not carry the same version on its stamps (an additive allowance, so the product's own documents still validate); every other check is untouched, and an unsupported resource type, a contained resource, a modifier extension or an unresolved reference is still refused exactly as before.
- **Author/verifier/sign-off identities without new resources.** The author reuses the observation's existing `performer` Practitioner; the verifier and sign-off, which exist only in the visit record, are referenced by `who` as an identifier (`urn:saha:user`) plus display name, so older documents keep their resource shape (no extra `Practitioner` resources). Ordinary visits with no recorded author, review, sign-off, entered unit or override produce exactly the earlier output.

## Evidence

- 51 contract checks (`tests/fhir-provenance-contract.mjs`): the pinned rule set is unchanged; synchronous sign-off resolution (current, withdrawn, stale version, non-confirmed); observation agents (author plus the latest verifier with state and reason); the structured override extension for an unusual value (entered value/unit, reason, tier, ranges version and ranges, recorder, confirmation) and none for an in-range value; a document with per-observation `Provenance` (author reusing the performer, verifier as an identifier+display reference, coded verification state) and a visit-level sign-off `Provenance` targeting the Composition, all passing the unchanged validator; ordinary visits unchanged (no `Provenance`, no extension, one Practitioner); and the rule set still refusing unsupported and unresolved resources.
- Regression contracts re-run and passing, unchanged counts: `fhir-validate-contract` (20, incl. the 14-case corpus), `fact-provenance-contract` (41), `fact-verification-contract` (37), `value-override-contract` (53).
- `node node_modules/typescript/bin/tsc --noEmit` passes with no errors.
- The full HTTP/D1 and UI suites were not run for this slice (the parallel-agent isolation rules reserve them for the integrator).

## Limits

- The `Provenance` resources and the override extension use Saha's own code systems and extension URLs (`urn:saha:*`, a `provenance-participant-type` code for the agent type). They are not profiled by an HL7 FHIR validator, a terminology server or the NRCeS implementation guide; that remains open for BR-INT-11. The document still passes only the local structural subset.
- The verifier and sign-off are referenced by identifier and display name, not by full `Practitioner` resources in the bundle; element-level author/device, receipt/effective time and transformation lineage for every resource remain open (R22).
- Programme answers and visit notes are not exported as FHIR resources, so this slice's provenance covers the exported measurements only; note/answer authors and reviews remain in the Composition narrative and note text as before.
- The FHIR example download (`lib/saha/fhir.ts`, `?format=example`) is unchanged: it is a demonstration collection, not the validated document, and keeps only its note text.
- No route, command, migration or MIS payload changed. The sign-off reflected is the latest matching the visit version; the asynchronous facts-and-answers hash re-check used by the send gate is not repeated at document-build time (documents are built only from a current confirmed visit).

## Notes for the integrator

- The provenance helpers are inlined in `lib/saha/fhir-document.ts` (the single shared file this slice edits) rather than a new module, so the ~16 existing contract harnesses that transpile `fhir-document.ts` keep working unchanged. If you prefer a separate `lib/saha/fhir-provenance.ts`, every harness's transpile list must gain `fhir-provenance`.
- `inspectDocument` now permits `Provenance` as a resource type. This is additive; the rule-set id/version/basis and the regression corpus are untouched.
