# Scoped coding-agent prompt
Copy and fill the block. Missing facts remain unknown.

```text
Work on APLYD: [CHANGE/SCOPE]. Repository/branch: [LOCATION]. QA package: [PATH]. Canonical requirements/Linear IDs: [SOURCES]. Authorized environments/actions/budgets: [BOUNDARIES]. Actual decision owners: [OWNERS].
Read the QA task-routing table, relevant AC/change request and existing repository instructions/test conventions. Classify risk; use the Low-tier fast path when eligible. Load only applicable sections; do not recursively load this package or create a full planning hierarchy for a small fix.
For scoped QA/release work bind existing vision/strategy/roadmap/release-goal/release/epic/story/AC/task IDs, shared Ready/Done and AI assurance. Preserve canonical authority. Create only records needed for this task. Resolve minimum context for the current action; block that dependent action if missing while continuing independent work. First-release numeric targets may use approved predeclared provisional targets; undefined targets never pass.
Implement and execute meaningful risk-based checks within authorization. Pin build/config/data and relevant model/prompt/corpus. Use case IDs in code and normalized registers where maintained. Preserve immutable failures, retests and diagnostic runs; statistical repetition must follow a predeclared protocol. Never weaken assertions/targets or retry until green to hide failures.
For release assessment, use an independently reviewed canonical PM criteria export and pinned count/ID-version-set/source-byte hashes in scope.json; never derive expected population from QA rows. Require reviewed severity decreases and same-case same-candidate retests. Use confined relative references and a portable evidence_root. Verify actual source/pin human-review or independent-reconciliation controls before real release reliance; package templates do not install them. Configure evidence_root and validate PM mapping against the installed full catalogue. Run checker/qa_lint.py on scoped registers and report its structural/coverage output separately from actual product results. The checker cannot verify evidence truth, omitted requirements, approvals or total readiness. Do not invent owners, product facts, applicability, passes or approvals. Do not self-authorize external writes, merges/deployments or invasive/production tests.
Finish authorized work and report concrete changes, actual check/evidence results, numerator/denominator coverage, failed/blocked/skipped/not-run/stale checks, residual risks and the next required decision. Keep quality/approval/readiness/delivery/learning distinct. Use release mode only for an actual release assessment with the full scoped evidence.
```
