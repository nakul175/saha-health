# Code IDs and parallel edits
Preserve existing canonical product IDs. New QA IDs use `TC-<scope>-<unique>`, `RUN-<unique>`, `BUG-<unique>`, `RISK-<scope>-<unique>`, `EX-<unique>`. Use a UUID or collision-resistant repository allocator for unique; demo IDs are reserved to examples. Never allocate by CSV row count. Versions are explicit immutable strings. IDs must contain only letters/digits/underscore/hyphen/dot, starting with a letter.

Every automated test carries its case ID/version in a discoverable marker, annotation or name, e.g. `qa:TC-AUTH-a17@v1` in a test docstring/comment next to the implementation. Framework-native tags are preferred where supported. Add a case register `automation_locator` as `repository-relative-path#symbol-or-line` and optional `marker`. One code test can list multiple IDs only if it asserts each linked outcome. Moved code updates locators in the same PR. Manual cases explicitly use `mode=MANUAL` and a procedure reference. The checker verifies local automatic locator files and marker strings exist; it cannot prove the marker is attached to a meaningful test or that its assertions implement the AC.

Runs are immutable append-only observations; defects are immutable append-only events with unique event IDs and predecessor links. Fix/retest/closure creates a new event, retaining the initial failure. Requirement/case/mapping changes use reviewed versions and invalidation. Do not share a writable CSV across concurrent agents: assign separate record IDs and per-agent change files/branches, then have one integrator validate and append deterministically. CSV register mutation is serialized in reviewed merges. Never resolve duplicate records by silently overwriting one.

Run selection is explicit via a coverage snapshot: exact build/artifact/config/environment/data and case/AC versions. Latest timestamps alone are unsafe. Each mapping selects an approved qualification run ID for that snapshot. Diagnostic runs cannot replace it. When a defect is fixed, select the valid retest with history links; preserve original failure. The checker verifies scope matches but does not approve run selection.

## v1.2 change review
Changing the canonical criteria snapshot or its scope pins requires source-owner review; do not rebuild expected population from QA rows. Defect severity decreases carry reviewed rationale; case identity remains stable through events. Evidence-root configuration belongs to scope and is independent of register location.
