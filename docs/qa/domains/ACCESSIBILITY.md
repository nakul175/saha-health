# Accessibility validation
For applicable web interfaces propose WCAG 2.2 Level AA as the target, subject to actual product obligations and scope. Record standard version, covered screens/journeys, technologies and any stricter required standard. Automated scan success cannot establish conformance.

Combine automated checks with manual keyboard-only use, focus order/visibility/obscuration, screen-reader names/roles/states, headings/landmarks, errors and instructions, contrast, zoom/reflow, text spacing, target size, dragging alternatives, authentication, media alternatives and timing controls. Test loading/error/empty/modal states and critical journeys with the declared browser/assistive technology matrix.

For every selected criterion record ID, applicability rationale, method, expected outcome, observed evidence and result. Run with representative users where feasible; distinguish usability feedback from criterion verification. Visual inspection alone cannot verify accessible semantics. Apply native/mobile accessibility standards when relevant; do not assume web WCAG fully covers them.

Mandatory criterion failures remain unmet requirements. Bound any eligible exception by authority and scope; do not claim whole-product conformance from a sampled screen set. Preserve reproducible manual notes and tool versions.
