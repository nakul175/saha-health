# Adoption checklist
## Initial setup
- [ ] Copy into product repository `docs/qa/`; merge testing AGENTS instructions into root instructions.
- [ ] Appoint actual quality, specialist and release owners; record decision authority.
- [ ] Fill product context using authoritative product docs; pin versions and sources.
- [ ] Map existing vision/roadmap/release/epic/story/AC/task IDs without renaming them.
- [ ] Link existing shared readiness/completion and AI assurance records.
- [ ] Declare AI/personal-data/domain applicability; track unresolved decisions.
- [ ] Inventory existing suites, tooling and evidence before adding tests.
- [ ] Define risk register and measurable gates with owners, sources and uncertainty rules.
- [ ] Configure authorized environments, synthetic fixtures and access/retention.

## Pilot one release or story
- [ ] Fill strategy, release plan, scenarios/cases and traceability.
- [ ] Implement meaningful positive/negative/failure tests proportional to risk.
- [ ] Execute actual checks; preserve first failures and all reruns.
- [ ] File real defects with reproducible evidence and verify fixes.
- [ ] Review coverage gaps and specialist/manual checks.
- [ ] Configure and safely verify GitHub required checks; document enforcement.
- [ ] Use stable Linear/GitHub IDs and bidirectional links.
- [ ] Produce readiness report and obtain real decision-owner approval.

## Sustain
- [ ] Define rollout stop/rollback and observation owner/window.
- [ ] Review incidents, user outcomes, escaped defects and flakiness.
- [ ] Update risk/coverage/roadmap from learning; invalidate affected evidence.
- [ ] Version policy changes and periodically review exception expiry and evidence access.

Completing this checklist configures the process; only observed product evidence establishes product test outcomes.

## v1.1 additions
- [ ] Configure normalized scope/AC/case/mapping/selection registers and PM binding.
- [ ] Choose task routing and adopt the Low-tier fast path.
- [ ] Run checker tests; configure structural and release-mode checks at appropriate stages.
- [ ] Add code case markers, collision-resistant IDs and serialized register integration.
- [ ] Approve provisional targets/repetition protocols before qualification where needed.
- [ ] Review the fictional full lifecycle example without treating it as product evidence.

## v1.2 release integrity
- [ ] Freeze a complete independently reviewed PM criteria export; bind count, ID/version hash and source-byte hash in scope.json.
- [ ] Protect scope/source pin changes with actual reviewer-controlled workflow.
- [ ] Configure evidence_root or use --evidence-root for moved registers.
- [ ] Validate PM mapping against the installed full catalogue; aliases/prefixes are not fields.
- [ ] Require reviewed severity downgrades and same-case, same-candidate defect retests.

## v1.3 required source governance
- [ ] Install customized human CODEOWNERS rules for source, pins and validation controls in the actual repository.
- [ ] Configure required code-owner review/fresh-review/required-check/bypass settings and record them.
- [ ] Verify safe source-narrowing and control-change PRs cannot merge without actual required owner review.
- [ ] Complete source-protection-verification before using this process for real release decisions.
- [ ] Use portable evidence roots and confined relative references; document any explicit machine-local root exception.
