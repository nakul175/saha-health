# Implementation boundary

R11 / v1.3-readiness is a private synthetic engineering application. It supports a bounded care-record workflow with human review and per-destination outcomes. It does not deliver the entire original design. All formal BRD acceptances are pending.

## Runtime and persistence

The React/Vinext UI calls sixty-six HTTP method/route handlers (R11 had thirteen; slices 0b-3, 0b-4, 1, 1b, 1c, 1d, 1e, 2b, 2d, 2f, 2h, 3i, 4a, 4b, 4c, 4e, 4f, 5b, 6a, 6b, 6c, 6d, 6i, 6j, 6l, 6m, 6n, 6q, 6v, 6y, 7a, 7g, 10b, 10c, 10d, 10e, 10h and the independent anaemia-provider demo added the patient-list (GET, and POST for search since 6q), patient-detail, work-list, household, caseload, identity-case, roster-preview, media upload, playback and removal, referral-escalation, referral-request queue, action-plan, emergency-access, rights, retention, indicator (GET, and POST since 6l), exception-queue, audit-chain, provider-sandbox, data-exit, environment, fixture-migration, programme-migration, pack-installation, patient-import, record-import, workforce-import, import-rejections, delegation, worker-activity, incentive-claims, alert-inbox, trace, aggregate-report, ABDM, identifier-search, record-opened and notification-channel (owners only), facility-scope, purpose-scope and reassignment routes). Mutations normally enter `POST /api/commands` through a composed Zod discriminated union. `lib/saha/server.ts` authenticates and dispatches; domain modules validate state and authority; `lib/saha/store.ts` commits through D1 batches under one of two guards: a per-patient guard for the 57 certified patient commands in `lib/saha/partition.ts` (slice 10g added `raiseDispute`, `resolveDispute` and `withdrawSignOff`; slice R33 added `reuseFact`), or the organisation-wide guard for everything else (development slice 0a). Since slice 6j each commit also links its audit events to the organisation's single audit chain; a commit that loses the race for the next sequence number is rebuilt on the new head. Provider execution modules checkpoint before external calls and preserve uncertainty afterward. Outbound provider, partner and Cloudflare Access key requests use redirect mode `manual` (slices 0c-1 and 11f; the Workers runtime rejects `error`): a redirect is refused as a failed or unconfirmed result and never followed.

There are 35 application schema tables and nineteen immutable SQL migrations, 0000–0018 (0007 households, 0008 caseload transfers, 0009 identity cases, 0010 rights requests, 0011 retention, 0012 media, 0013 audit-chain columns, 0014 alert delivery, 0015 the notification message log, 0016 the scheduled rotation cursor, 0017 two audit indexes and 0018 the limit reservations were added by development slices 1, 1b, 1c, 6b, 6c, 2b, 6j, 6v, 10b, 13d, 13e and 14a). The local restore report counts 31 SQLite tables because it includes D1 metadata. Several tables contain versioned JSON aggregates; the original PostgreSQL foundation schema and 26 proposed entities are a design reference. D1 has no implementation of the proposed PostgreSQL RLS model.

Since slice 0a, certified patient commands load only the named patient plus organisation-level state, and concurrent writes on different patients no longer conflict. Since slice 0b, those commands can answer with a partition delta that the workspace merges, so a write returns kilobytes rather than the whole organisation. Since slice 0b-2, the workspace read selects only the viewer's permitted patients in SQL, so an ASHA's read no longer grows with the organisation. Since slice 0b-3, a workspace client that asks for paging and whose non-ASHA scope exceeds 500 people receives only the patients it has opened, lists the scope through the paged, searchable `GET /api/patients` and loads one patient through `GET /api/patients/detail`; a local probe measured a supervisor's read at 34 ms and 5 KB with 50,006 people instead of 1.9 s and 38.6 MB. Clients that do not ask, and ASHAs, still receive every permitted patient. Since slice 0b-4, a paged workspace's My work, follow-ups, referral tracker and Submissions are built on the server over the whole scope with the same functions the unpaged workspace uses (`GET /api/worklists`), instead of covering only opened records. See [slice 0a](current/SLICE-0A-STORAGE.md), [slice 0b](current/SLICE-0B-DELTAS.md), [slice 0b-3](current/SLICE-0B3-PAGED-PATIENTS.md) and [slice 0b-4](current/SLICE-0B4-SERVER-WORKLISTS.md). ## R11 evidence and authority

The saved 27 September qualification contains 902 HTTP/D1 assertions, 361 contract/checkpoint assertions and 21 local encrypted restore assertions, totaling 1,284. These tests use synthetic fixtures. The 18-case evaluation corpus contains 16 English examples and two Hindi examples; the English subset passes and Hindi eligibility fails. The corpus is tiny, fixed and known to the implementation. It cannot establish NFR-16 or clinical accuracy.

Governance activation binds the manifest, model/agent version, reviewers, owner, dates, intended-use context and dependencies. Current authority is checked again before use. A technical connection test alone grants no clinical authority. Local records of review do not establish that an actual professional or institution has approved use.
