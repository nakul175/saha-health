# Implementation boundary

R11 / v1.3-readiness is a private synthetic engineering application. It supports a bounded care-record workflow with human review and per-destination outcomes. It does not deliver the entire original design. All formal BRD acceptances are pending.

## Runtime and persistence

The React/Vinext UI calls twenty-six HTTP method/route handlers (R11 had thirteen; slices 1, 1b, 1c, 1d, 2b, 4a, 6a, 6b, 6c, 6d and 7a added the household, caseload, identity-case, roster-preview, media upload, playback and removal, referral-escalation, emergency-access, rights, retention, indicator and ABDM routes). Mutations normally enter `POST /api/commands` through a composed Zod discriminated union. `lib/saha/server.ts` authenticates and dispatches; domain modules validate state and authority; `lib/saha/store.ts` commits through D1 batches under one of two guards: a per-patient guard for the 39 certified patient commands in `lib/saha/partition.ts`, or the organisation-wide guard for everything else (development slice 0a). Provider execution modules checkpoint before external calls and preserve uncertainty afterward.

There are 30 application schema tables and thirteen immutable SQL migrations, 0000–0012 (0007 households, 0008 caseload transfers, 0009 identity cases, 0010 rights requests, 0011 retention and 0012 media were added by development slices 1, 1b, 1c, 6b, 6c and 2b). The local restore report counts 31 SQLite tables because it includes D1 metadata. Several tables contain versioned JSON aggregates; the original PostgreSQL foundation schema and 26 proposed entities are a design reference. D1 has no implementation of the proposed PostgreSQL RLS model.

Since slice 0a, certified patient commands load only the named patient plus organisation-level state, and concurrent writes on different patients no longer conflict. Since slice 0b, those commands can answer with a partition delta that the workspace merges, so a write returns kilobytes rather than the whole organisation. Since slice 0b-2, the workspace read selects only the viewer's permitted patients in SQL, so an ASHA's read no longer grows with the organisation. The initial workspace read still returns every permitted patient, which a local probe measured at 77 MB and 3.5 s for 100,000 people; paged lists are planned. See [slice 0a](current/SLICE-0A-STORAGE.md) and [slice 0b](current/SLICE-0B-DELTAS.md). The local load probe is engineering evidence, not a production throughput or latency qualification.

## R11 evidence and authority

The saved 27 September qualification contains 902 HTTP/D1 assertions, 361 contract/checkpoint assertions and 21 local encrypted restore assertions, totaling 1,284. These tests use synthetic fixtures. The 18-case evaluation corpus contains 16 English examples and two Hindi examples; the English subset passes and Hindi eligibility fails. The corpus is tiny, fixed and known to the implementation. It cannot establish NFR-16 or clinical accuracy.

Governance activation binds the manifest, model/agent version, reviewers, owner, dates, intended-use context and dependencies. Current authority is checked again before use. A technical connection test alone grants no clinical authority. Local records of review do not establish that an actual professional or institution has approved use.
